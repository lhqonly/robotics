# 性能验证记录（2026-07-08）

目标：验证“MCU 本地 1kHz 控制基线 + PC/ROS 高频下发 + ROS 状态/链路健康回传”的第一阶段可行性。

## 环境

- 板子：STM32F103RB，USART1 `/dev/ttyUSB0`，921600 8N1，DMA。
- Agent：`tools/run-bridge.sh /dev/ttyUSB0 921600`，默认 `MICROROS_AGENT_VERBOSITY=1`。
- 固件：新增 `com_control_task` 1kHz 本地控制骨架，micro-ROS spin/read 等待收紧到 1ms 量级。
- PC 节点：`pc_cmd.launch.py`，QoS `RELIABLE / KEEP_LAST / depth=1`，`rtt_warn_ms=10`，`rtt_deadline_ms=50`。

## 结果

| PC 下发频率 | `/com/tp_mcu_status` 观测频率 | LinkHealth 结果 |
|---:|---:|---|
| 20 Hz | 20.0 Hz | 稳定，`sent=220 matched=219 lost=0 inflight=1` |
| 30 Hz | 29.7 Hz | 吞吐基本跟上，但出现丢包，末尾 `lost=27` |
| 40 Hz | 37.2 Hz | 吞吐不足，出现丢包/重复，末尾 `lost=21 duplicate=2` |
| 50 Hz | 42.2 Hz | 明显进入瓶颈，末尾 `lost=99` |
| 75 Hz | 42.1 Hz | 大量丢包，末尾 `lost=360` |
| 100 Hz | 39.1-45.5 Hz | 大量丢包，末尾 `lost=509` |
| 200 Hz | 39.2 Hz | 严重拥塞，`sent=2144 matched=383 lost=1756 duplicate=93` |

## 结论

- 当前 `RELIABLE + micro-ROS serial + 921600 + F103` 往返闭环稳定点约为 20 Hz。
- 200 Hz 目标未达成；瓶颈不是单一 PC timer 或 agent 日志，固件已收紧到 1ms 后仍卡在约 40 Hz 状态回传。
- 后续优化应优先验证：
  - 控制命令 topic 是否改为 latest-only / best-effort，状态诊断保留 reliable。
  - XRCE stream history、MTU、baudrate 对吞吐的影响。
  - MCU 本地控制闭环继续保持独立，PC/ROS 不参与每个 motor-control tick。
