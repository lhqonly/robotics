# 任务卡 004:M2离线内存与通信预算收敛
- 负责开发:Tom
- 负责测试:Gill
- 依赖:任务卡 003、现有 `build-motor` / `build-motor-opt` ELF、M2 telemetry sweep 工具

## 目标

在 SWD/USB-TTL 不可见期间，继续收敛 M2 motor-enabled 固件的静态内存占用和通信预算候选，产出可复查的候选矩阵与恢复硬件后的 smoke 顺序；不得把静态证据标记为真机完成。

## 接口契约

离线报告入口：

```text
tools/firmware-size-report.sh <elf>
tools/summarize-firmware-memory-plan.sh
tools/motor-m2-telemetry-sweep.py --pass-only
tools/com-status-report.sh <tag>
```

真机恢复后的判定入口保持不变：

```text
tools/recommend-motor-m2-smoke-command.sh
tools/check-motor-m2-smoke-evidence.py log/motor-m2-smoke/<tag>
```

## 实现要点 / 约束

- 默认固件配置保持不变；`build-motor-opt`、stack 704/640 words、heap/MSP reserve 缩减都只能作为候选。
- `firmware-size-report.sh` 必须能把 M2 `exo_motor_msgs` 的 ROSIDL metadata 拆分到 `JointTarget`、`JointState`、`MotorHealth`，避免全部落入 `other_rosidl_metadata`。
- 921600 baud 的低遥测组合只能作为 `thin_margin` 静态候选；2Mbps `first_smoke` 是首轮真机 smoke 候选。
- 离线报告必须明确：构建成功、静态 RAM/Flash、静态 UART 预算和工具 PASS 都不能替代 ROS graph/topic 闭环、reconnect/soak、stack HWM 或 `/com/tp_mcu_status` 并发验证。

## 验收标准(给 Gill)

- `tools/test-firmware-size-report.sh` 能验证默认 ELF 与 motor ELF 的 ROSIDL metadata breakdown；motor ELF 存在时，`JointTarget`、`JointState`、`MotorHealth` 必须为非零。
- `tools/test-com-status-report.sh` 能验证 handoff 报告展示 M2 motor ROSIDL metadata breakdown。
- `tools/test-motor-m2-telemetry-sweep.sh` 能验证 921600 low telemetry 候选仍标记为 `thin_margin`，默认 20ms/200ms @ 921600 不被误报为 pass。
- `tools/test-offline-contracts.sh` 通过。
- 报告未声明任务卡 003 完成；真机 smoke、topic 闭环、frame_id 注入、栈水位、MSP/heap、reconnect/soak 仍保留为硬件恢复后的未完成项。

## 不在本卡范围内

- 不修改默认 motor telemetry period。
- 不修改默认 micro-ROS stack 或 linker heap/MSP reserve。
- 不重建或替换 `libmicroros.a`。
- 不声明 `/motor` 真机验收完成。
