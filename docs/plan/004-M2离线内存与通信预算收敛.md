# 任务卡 004:M2离线内存与通信预算收敛
- 负责开发:Tom
- 负责测试:Gill
- 依赖:任务卡 003、现有 `build-motor` / `build-motor-opt` ELF、M2 telemetry sweep 工具

## 目标

在 SWD/USB-TTL 不可见期间，继续收敛 M2 motor-enabled 固件的静态内存占用和通信预算候选，产出可复查的候选矩阵与恢复硬件后的 smoke 顺序；不得把静态证据标记为真机完成。

## 当前进度

- 2Mbps first smoke 已完成真机 strict PASS：`log/motor-m2-smoke/throughput_qos_lightprobe_20260710_112543`。它证明 200Hz enabled target、10kHz local loop、20ms state、200ms health、motor telemetry best-effort、轻量 `/com` liveness probe 可在 2Mbps 下同时通过 topic/seq/TTL/clamp/frame_id/soak/stack-HWM gates。
- 921600 low telemetry 已按本卡要求作为 post-2Mbps comparison 跑过，但 strict smoke 未 PASS。`500ms state + 1000ms health @ 921600` 静态预算为 `29.91%`，只有 `0.09%` margin；运行期 evidence 显示它接近边界：`probe10` 轮 target receive 为 `880/1000`，`probe5` 轮 target receive 可到 `971/1000`，但最终 state 在 500ms telemetry 与 100ms TTL 下变为 stale，未满足 final `target_fresh/enabled` gate。
- 因此 921600 low telemetry 仍只能标记为 `comparison_only / strict_smoke_fail`，不能作为默认 profile、first smoke 替代或内存/通信默认收敛依据。
- 验证工具已针对低遥测做加固：clamp capture 支持重复发布同一 seq 捕获 fresh state；enabled soak final-state post-spin 随 state period 延长；enabled-soak `/com` probe 默认降为 5Hz/`status_every_n=1`，减少验证负载。

## 实现要点 / 约束

- 默认固件配置保持不变；`build-motor-opt`、stack 704/640 words、heap/MSP reserve 缩减都只能作为候选。`704 words` 是 stack-only 中间降档候选，不是默认配置。
- `firmware-size-report.sh` 必须能把 M2 `exo_motor_msgs` 的 ROSIDL metadata 拆分到 `JointTarget`、`JointState`、`MotorHealth`，避免全部落入 `other_rosidl_metadata`。
- 921600 baud 的低遥测组合只能作为 `thin_margin`/`PASS_THIN` 静态对照；2Mbps `first_smoke` 是首轮真机 smoke 候选。报告中的保守 pass-only 摘要必须使用 `--min-margin-pct 1`，避免把 921600 thin row 当成稳健 PASS。
- 离线报告必须明确：构建成功、静态 RAM/Flash、静态 UART 预算和工具 PASS 都不能替代 ROS graph/topic 闭环、reconnect/soak、stack HWM、MSP/heap 或 `/com/tp_mcu_status` 并发验证。
- M2 smoke evidence 目录必须由 `raw.sha256`/raw runtime 文件证明采集完整性，不能接受单文件 template 伪装为 PASS。

## 验收标准(给 Gill)

- `tools/test-firmware-size-report.sh` 能验证默认 ELF 与 motor ELF 的 ROSIDL metadata breakdown；motor ELF 存在时，`JointTarget`、`JointState`、`MotorHealth` 必须为非零。
- `tools/test-com-status-report.sh` 能验证 handoff 报告展示 M2 motor ROSIDL metadata breakdown。
- `tools/test-motor-m2-telemetry-sweep.sh` 能验证 921600 low telemetry 候选在默认矩阵中仍标记为 `thin_margin`，在 `--min-margin-pct 1` 保守摘要中降级为 `PASS_THIN` 并从 `--pass-only` 中排除；默认 20ms/200ms @ 921600 不被误报为 pass。
