# 电机控制阶段路线图：CyberGear 优先，CubeMars 后续分支

> 角色：Elon 规划。
> 日期：2026-07-09。
> 适用分支：`feature/cybergear-motor-control`。
> 设计输入：`docs/01-ros2-microros-serial/17-电机控制接口抽象设计.md`、`docs/01-ros2-microros-serial/18-重要-ROS命名空间与SoC-MCU边界.md`。

## 1. 总目标

先用小米 CyberGear 完成低成本电机控制可行性验证，同时把工程边界设计成后续可以快速切换 CubeMars 或其他 CAN 力矩电机。

核心判断：

```text
ctrl node -> motor topic -> MCU
```

不是：

```text
ctrl msg -> motor msg -> MCU
```

`/ctrl/` 是“谁算目标”，`/motor/` 是“关节执行契约”，`/com/` 是“通信健康观测”。`micro_ros_bridge` 只是 ROS2 与 micro-ROS 的桥，不解析业务命令。

## 2. 阶段路线

| 阶段 | 任务卡 | 目标 | 是否需要真实电机 |
|---|---|---|---|
| M0 | `001-M0-PC直连CyberGear与Mock.md` | PC 直连 CyberGear / mock 跑通第一条 motor 链路 | mock 不需要，CyberGear bring-up 需要 |
| M1 | `002-M1-exo_motor_msgs与ROS接口.md` | 定义厂商无关 ROS 消息、topic、service 契约 | 不需要 |
| M2 | `003-M2-MCU订阅JointTarget本地控制.md` | MCU 订阅 `/motor/tp_joint_target`，10kHz 本地消费 latest target | 不强制，需要现有 STM32 |
| M3 | `004-M3-CyberGear-CAN-Backend.md` | 实现 CyberGear CAN backend，接入 Motor HAL | 需要 CyberGear + CAN 硬件 |
| M4 | `005-M4-验证安全与台架验收.md` | 安全状态机、压测、台架验收闭环 | 需要台架 |
| M5 | `006-M5-CubeMars后续分支准备.md` | CubeMars 分支准备，不污染 CyberGear 交付 | 可先无硬件设计，实测需要 CubeMars |

## 3. 推荐派发顺序

第一张建议交给 Tom：

```text
docs/plan/001-M0-PC直连CyberGear与Mock.md
```

理由：

- 可以先做 mock 和 CyberGear frame codec，不等真实电机。
- CyberGear 到货后，直接用同一张卡继续 PC 直连 bring-up。
- 它能最快暴露 USB-CAN、供电、协议资料是否靠谱。

第二张并行或紧随其后：

```text
docs/plan/002-M1-exo_motor_msgs与ROS接口.md
```

理由：

- M1 是 M2/M3/M4 的共同契约。
- 如果 Tom 一人开发，建议 M0 mock 先跑通，再 M1 正式建包。
- 如果多人并行，M0 和 M1 可并行，但接口字段必须以 M1 为准。

## 4. 合并策略

建议：

1. M1 的 `exo_motor_msgs`、topic/service 命名、mock contract test 属于共同契约，应优先评审并合入 `main`。
2. M0/M3 的 CyberGear 真实厂商实现可以留在 `feature/cybergear-motor-control` 迭代。
3. M5 的 CubeMars 从包含共同契约的 `main` 单独开 `feature/cubemars-motor-control`，不要从 CyberGear 分支继续开。
4. 厂商分支中的硬件试错 commit 可以本地密集，但远端 push 前应整理，避免历史过密。

## 5. Gill 验证总原则

Gill 每个阶段都要验证三件事：

1. **接口契约没有泄露厂商细节**：ROS topic/service 不出现 CyberGear/CubeMars 原始命令 ID、扩展帧编码、厂商单位范围。
2. **链路可观测**：每个目标都有 seq，可追踪 received/applied/state；关键延迟、超时、fault、stale target 有计数。
3. **安全默认保守**：上电不助力，过期不继续执行，fault 不自动恢复到 active control。
